# Nowcoder Backend Interview Digest Skill

`nowcoder-backend-interview-digest` 是一个 Codex skill，用来从牛客网整理互联网大厂后端/后台相关面经，并在有飞书 webhook 时同步发送复习清单。

它适合这些场景：

- 想按时间顺序查看牛客最新后端面经
- 想筛选阿里、腾讯、字节、美团等大厂面试题
- 想过滤掉太水的帖子，只保留高质量后端问题
- 想把结果整理成飞书消息，并在同一次任务里直接发到群里每日复习

## 功能概览

默认流程是：

1. 使用 `web-access` 打开牛客面经中心或搜索结果。
2. 按最新时间顺序扫描帖子。
3. 遇到目标大厂 + 后端方向帖子就加入候选池。
4. 打开候选帖子详情页，提取公司、岗位、轮次、时间、链接和问题。
5. 按质量规则筛选问题。
6. 默认输出 `3 篇帖子 × 每篇 3 题 = 9 题`。
7. 生成飞书消息格式，并在有 webhook 时立即联动 `feishu-webhook-message` 发送。

## 默认岗位范围

包含：

- 后端、后台、服务端
- Java、C++、Go/golang
- AI 后端、AI 后台、AI 应用开发
- Agent 开发
- 平台开发、基础架构、云平台、中间件

默认排除前端、产品、运营、测试、纯 HR 面、纯吐槽帖、无具体技术问题的帖子。

岗位规则在：

```text
references/role-keywords.md
```

## 什么算高质量问题

优先保留这些类型：

- 场景设计题：秒杀、订单超时、限流、日志、定时任务、海量数据
- 项目深挖题：请求链路、登录系统、缓存一致性、服务拆分、业务瓶颈
- 后端基础深挖：TCP、MySQL MVCC、Redis、线程池、锁、CAS、IPC
- 分布式系统：服务发现、Raft、微服务调用、多级缓存、分布式事务
- AI 后端/Agent：RAG、SSE 高并发、模型 API 限速、上下文管理、MCP、AI coding

会降低优先级的问题：

- 自我介绍
- 反问
- 能不能实习
- “线程池是什么”这类过泛问题
- “讲讲项目”但没有追问细节的问题

质量规则在：

```text
references/quality-rules.md
```

## 输出格式

默认生成并发送飞书文本消息；如果没有 webhook，则输出待发送文本。例如：

```text
【牛客大厂后端面经复习清单】

本次筛选：3 篇帖子 / 9 个问题
公司范围：阿里、腾讯、字节、百度、美团、京东、拼多多、快手、网易、小米、蚂蚁
方向：后端 / 后台 / AI后端 / Agent开发 / 平台开发

1. 字节跳动｜后端开发｜二面
面试时间：2026-05-21
来源：https://www.nowcoder.com/...

Q1：无锁队列如何实现？相比普通队列有什么优劣，为什么不是所有场景都适合？
考察点：并发编程、CAS、锁竞争
```

完整模板在：

```text
references/feishu-template.md
```

把整个 skill 目录放到 Codex skills 目录：

```bash
~/.codex/skills/nowcoder-backend-interview-digest
```

目录结构应类似：

```text
nowcoder-backend-interview-digest/
```

安装后重启 Codex，让新 skill 被加载。

## 依赖

建议同时安装：

- `web-access`：访问牛客、读取动态页面、使用浏览器登录态
- `feishu-webhook-message`：把整理好的复习清单发送到飞书群机器人

如果明确不发送飞书，只输出 Markdown/文本，也可以不安装飞书 skill。

## 使用示例

可以这样对 Codex 说：

```text
爬牛客大厂后端面经，筛 3 篇，每篇 3 个高质量问题。
```

也可以指定范围：

```text
只看腾讯、字节、美团，岗位包含后端和 Agent 开发，整理成飞书消息。
```

如果只想生成文本，需要明确说明：

```text
帮我从牛客抓最新大厂后台开发面经，先不要发送飞书，只输出复习清单。
```

## 注意事项

- 牛客页面可能需要登录态；使用 `web-access` 时优先用已登录浏览器。
- 不要复制整篇面经，只整理短问题和学习提示，保留原帖链接。
- 如果帖子只写了发布时间，没有明确面试时间，应标注为“面试时间：未注明，帖子发布于 ...”。
- 抓取时不要一次打开大量页面，避免触发风控。
- 飞书 webhook 属于敏感信息，不要写入仓库。
- 整理和发送默认是同步完成的；只有用户明确要求不发送时才跳过飞书。

- 原则：时间顺序优先，质量筛选优先，保留来源链接
